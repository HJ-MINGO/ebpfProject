# execmon 최소 커널 호환성 누락

작성일: 2026-10-25

## 증상

기존 테스트 시나리오와 일부 안내 문서가 `BPF_MAP_TYPE_RINGBUF`의 도입 버전인 Linux 5.8을 `execmon` 전체 소스의 최소 기준처럼 설명했다.

## 확인된 사실

- `BPF_MAP_TYPE_RINGBUF`와 `bpf_ringbuf_reserve()` 계열은 Linux 5.8부터 제공된다.
- 현재 `execmon/src/execmon.bpf.c`는 PPID를 읽기 위해 `bpf_get_current_task_btf()`를 호출한다.
- `bpf_get_current_task_btf()` helper는 Linux 5.11부터 제공된다.
- 따라서 **현재 소스를 수정하지 않고 실행하는 최소 커널 기준은 Linux 5.11**이다.

## 실행한 확인 방법

1. `execmon/src/execmon.bpf.c`에서 helper 사용 여부를 확인했다.
2. eBPF helper 및 map type 버전 문서를 대조했다.

## 원인

ring buffer의 최소 버전만 확인하고, 같은 프로그램에서 사용하는 helper의 도입 버전을 함께 점검하지 않았다.

## 해결 조치

- 테스트 시나리오의 최소 커널 기준을 Linux 5.11 이상으로 수정했다.
- 환경 점검에 `bpf_get_current_task_btf` helper 확인을 추가했다.
- 배포판별 `bpftool feature probe` 출력 차이를 고려해 ring buffer 확인을 `ringbuf` 패턴 기반으로 바꿨다.
- `guide.md`, `execmon/README.md`, BPF 소스 주석에도 같은 기준을 반영했다.

## 후속 확인 항목

- 새 실습 VM에서 `sudo bpftool feature probe kernel`으로 map type과 helper가 실제로 보이는지 확인한다.
- Linux 5.8~5.10을 지원해야 한다면 PPID 수집 방식을 별도 설계하고, 그 호환 경로를 독립적으로 빌드·실행 검증한다.

- [bpf_get_current_task_btf: Linux 5.11](https://docs.ebpf.io/linux/helper-function/bpf_get_current_task_btf/)
