# 2026-11-18 Rust 마이그레이션 진행 로그

## 완료 작업

- 기존 C + libbpf `execmon` 구현을 기준 구현으로 유지하기로 했다. Rust 마이그레이션 초기에는 기존 `execmon/` 디렉터리를 삭제하거나 변경하지 않는다.
- 저장소 최상위 `README.md`를 Rust 기반 마이그레이션의 목표, 범위, 보안 경계, 단계별 완료 기준 중심으로 다시 작성했다.
- 기존 진행 로그와 구분하기 위해 Rust 작업은 파일명과 본문에 `Rust`를 명시해 기록하기로 했다.
- Aya 공식 문서와 현재 VM 기록을 대조해, Linux 6.8의 기존 BTF·ring buffer·tracepoint 조건은 유지할 수 있음을 조사 노트에 기록했다.
- `execmon-rust/` Aya workspace를 추가했다. 커널 eBPF crate, 사용자 공간 loader crate, 공용 이벤트 ABI crate를 분리했으며, 첫 프로그램은 `sys_enter_execve` tracepoint를 load·attach하는 뼈대다.
- 대상 VM에서 Rust toolchain과 기존 eBPF 기능을 변경 없이 점검할 `execmon-rust/scripts/check-prerequisites.sh`를 추가했다.
- 기존 문서에 나온 `ebpf-lab` SSH 별칭으로 VM의 상태를 읽기 전용 확인하려 했으나, 현재 작업 환경에서는 호스트를 해석하지 못했다. 원문과 후속 조치는 `error/2026-11-18_Rust_VM_SSH_별칭_미해결.md`에 기록했다.
- 사용자가 MFA 접속한 실습 VM에서 Rust stable `1.100.0`, nightly `1.102.0-nightly`, `bpf-linker`를 설치하고 사전 조건 스크립트를 실행했다. BTF, ring buffer, current-task BTF helper는 available로 확인됐다.
- 같은 점검에서 `sys_enter_execve tracepoint: unavailable`이 나왔지만, tracefs가 두 표준 경로에 마운트됐고 `sudo test -r /sys/kernel/tracing/events/syscalls/sys_enter_execve/format`이 available을 반환함을 확인했다. 원인은 스크립트의 비-root 파일 권한 검사였으며, 검사만 `sudo`를 쓰도록 수정했다.
- 사용자가 VM에서 `cargo build --release`를 실행해 Aya workspace의 첫 release 빌드를 성공했다. `execmon-rust-common`이 아직 loader에서 쓰이지 않아 unused dependency 경고가 한 건 발생했고, attach 전용 단계에서는 이 의존성을 제거하도록 수정했다.
- 수정된 VM 사전 조건 스크립트에서 Rust toolchain, `bpf-linker`, Linux `6.8.0-147-generic`, x86_64, BTF, `sys_enter_execve` tracepoint, ring buffer, current-task BTF helper가 모두 available임을 확인했다.
- eBPF crate manifest의 `which` build dependency도 실제 build script에서 사용하지 않아 경고가 났다. 이는 테스트용 코드나 eBPF 기능이 아니라 Aya 템플릿에 남아 있던 미사용 의존성이다. workspace와 eBPF crate manifest에서 제거해도 빌드·verifier·attach 검증 범위는 바뀌지 않는다.
- VM의 `find target -type f -name execmon-rust -exec file {} \;` 결과로 두 종류의 산출물을 확인했다. Aya build output 아래의 `execmon-rust`는 `ELF ... eBPF` relocatable object이고, `target/release/execmon-rust`는 x86-64 사용자 공간 loader executable이다. 따라서 `execmon-rust-ebpf`의 lib target 경고는 eBPF 객체 미생성이 아니라 Cargo dependency 추적 경고다.

## 확인된 사실

- 현재 저장소에는 C eBPF 프로그램(`execmon.bpf.c`)과 C 사용자 공간 loader(`execmon.c`)가 있다.
- 기존 구현은 `sys_enter_execve` tracepoint와 `BPF_MAP_TYPE_RINGBUF`를 사용하며, PID·PPID·UID·`comm`·실행 파일 경로를 이벤트로 다룬다.
- 기존 설계는 명령행 인자(`argv`)와 환경 변수(`envp`)를 수집하지 않는다. Rust 버전도 이 최소 수집 원칙을 유지한다.

## 아직 확인하지 않은 항목

- 사용할 Rust eBPF 프레임워크와 의존성 버전은 아직 확정하지 않았다.
- Rust toolchain이 대상 Linux 실습 VM에 설치되어 있는지 확인하지 않았다.
- Rust eBPF 프로그램의 빌드, verifier 통과, load·attach, ring buffer 이벤트 수신은 아직 수행하지 않았다.
- Rust에서 커널 프로그램과 사용자 공간 간 공용 이벤트 구조체의 바이트 배치와 정렬을 아직 검증하지 않았다.
- Rust eBPF crate의 실제 빌드, verifier 통과, tracepoint attach는 아직 대상 VM에서 검증하지 않았다.
- 현재 Windows 작업 환경에는 `cargo` 명령이 없어 workspace metadata 확인과 빌드를 실행할 수 없었다. 이는 대상 Linux VM의 Rust 설치 상태를 의미하지 않는다.
- 대상 Linux 실습 VM의 접속 가능한 SSH 별칭 또는 호스트 정보가 현재 작업 환경에 제공되지 않았다.
- Rust loader의 verifier 통과, load·attach와 Ctrl-C 뒤 link 정리는 아직 검증하지 않았다.
