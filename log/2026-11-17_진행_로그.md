# 2026-11-17 진행 로그

## 완료 작업

- 저장소 최상위에 프로젝트 목표, 현재 상태, 데이터 흐름, 환경 요구사항, 빌드·검증 순서를 담은 `README.md`를 추가했다.
- Ubuntu 24.04에서 `bpftool`이 가상 패키지로 표시되어 독립 설치가 실패한 사례를 `error/2026-11-17_bpftool_가상_패키지_설치_오류.md`에 기록했다.
- `guide.md`와 `server_setup_guide.md`의 패키지 설치 명령에서 가상 패키지 `bpftool`을 제거하고, `linux-tools-common` 및 커널 버전별 tools 패키지를 사용하도록 바로잡았다.
- VM의 표준 소스 경로를 `~/workspace/ebpfProject/execmon`으로 명확히 하고, 서버 준비 가이드와 테스트 시나리오의 모호한 경로 안내를 수정했다.
- BPF object 컴파일에서 `vmlinux.h`와 `<linux/types.h>`의 타입 중복 정의 오류를 확인하고, BPF와 사용자 공간의 공용 헤더 include 경로를 분리하도록 소스를 수정했다.
- 실습 VM에서 `build/execmon.bpf.o` 생성에 성공했다. `file` 출력은 `ELF 64-bit LSB relocatable, eBPF`였으며, BPF 소스가 eBPF object로 컴파일됐음을 확인했다.
- generated skeleton을 만든 뒤 사용자 공간 loader를 빌드했고, `build/execmon`이 일반 Linux x86-64 ELF 실행 파일로 표시되는 것을 확인했다.
- 실습 VM에서 `sudo ./build/execmon`을 실행해 BPF program을 tracepoint에 load·attach했고, ring buffer를 통해 실제 `execve` 이벤트가 사용자 공간에 출력되는 것을 확인했다. `sshd`가 `/bin/bash`를 실행한 이벤트와 Bash가 `tail`, `df`, `who`, `sleep`, `head`를 실행한 이벤트가 관찰됐다.

## 현재 환경

- 사용자 보고 기준 실습 VM: Ubuntu 24.04, Linux `6.8.0-147-generic`.
- `bpftool`, `clang`의 버전 정보를 확인했다.
- BTF, ring buffer, `bpf_get_current_task_btf()`, `sys_enter_execve` tracepoint 기능 probe가 모두 `available`을 반환했다.

## 미확인 항목

- Ctrl-C 종료 뒤 BPF link 정리는 아직 검증하지 않았다.
- 반복 관찰된 `tail`, `df`, `who`, `sleep`, `head` 실행이 어떤 shell profile 또는 백그라운드 작업에서 발생하는지 확인하지 않았다.
